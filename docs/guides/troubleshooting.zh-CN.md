# 故障排查手册

## 安装器退出码

| 退出码 | 含义 | 处理方式 |
|---:|---|---|
| 2 | 参数、工具、版本或目标路径不合法 | 检查帮助、依赖和目标路径 |
| 3 | 发布资产缺失或无效 | 使用完整发布检出，不要从单个脚本安装 |
| 4 | 文件冲突、非普通文件或路径逃逸 | 审查目标文件和符号链接，不要直接覆盖 |
| 5 | upgrade 清单缺失、损坏或版本方向错误 | 恢复有效清单或执行人工迁移 |

遇到冲突时先运行 `--dry-run`。`--force` 会覆盖内容不同的普通文件，只能在
人工确认目标改动不需要保留时使用。它不会绕过非普通文件和路径逃逸保护。

## 升级失败

- 同版本或降级会被拒绝；必须使用更高的稳定语义化版本。
- 本地修改的受管文件不会被 `--upgrade` 覆盖，需要合并或保留修改。
- `retired` 表示新版不再提供该资产；安装器保留文件，是否删除由操作者决定。
- 不要手工伪造 manifest 校验和，这会破坏后续升级的可信边界。

## Feature 初始化失败

| 退出码 | 含义 |
|---:|---|
| 2 | Feature ID、profile、参数或 Workspace 路径错误 |
| 3 | 必要模板缺失或为空 |
| 4 | Feature 目录已经存在 |

Feature ID 只能包含字母、数字、点、下划线和连字符，并且必须以字母或数字
开头。失败的初始化使用临时目录，不应留下部分 Feature 目录。

## Workspace 验证失败

- 退出码 5：没有发现 Go Module；仅在确定不是 Go Workspace 时使用
  `--allow-no-go-modules`。
- 退出码 6：找不到 Go。
- 退出码 1：至少一个测试、race、vet 或 lint 检查失败。
- `PASSED_WITH_SKIPS` 不是完整通过，需要判断缺失工具是否属于发布门禁。

## 文档阶段无法完成

使用 `UNKNOWN`、`UNCERTAIN`、`NEEDS_VERIFICATION` 或 `BLOCKED` 记录缺口，
并保留状态为未完成。不要为了推进流程而猜测仓库职责、业务规则、数据所有权
或调用关系。

如果缺少产品决策、生产配置、外部仓库或执行权限，应记录所需输入和负责人，
待条件满足后从原阶段恢复。
